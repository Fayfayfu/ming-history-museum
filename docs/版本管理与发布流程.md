# 步入大明：版本管理与发布流程

## 1. 版本号

采用语义化版本 `主版本.功能版本.修订版本`：

- `修订版本`：修正文案、史实关系、画像路径、样式或其他缺陷，例如 `v0.2.1`。
- `功能版本`：新增人物、专题、制度馆、筛选维度或一批完整内容，例如 `v0.3.0`。
- `主版本`：数据格式、网址结构或整体交互发生不兼容变更，例如 `v1.0.0`。

每个正式上线版本必须同时具有：Git 提交、带说明的 Git 标签、Vercel 生产部署。三者对应同一份代码。

## 2. 日常开发

小改动可直接在 `main` 上完成。范围较大或风险较高的工作使用 `codex/功能名` 分支，验收后再合并回 `main`。不要把 `dist/` 提交到 Git；它是根据已提交源码生成的发布包。

高清原图、史料归档、结构化数据和生成脚本需要进入版本库；临时截图、缓存和本地依赖不进入版本库。

## 3. 发布门槛

正式发布前依次执行：

```bash
npm run build:museum
npm run audit:museum
npm run audit:portraits
npm run verify:institutions
npm run verify:institution-page
npm run verify:portraits
npm run verify
npm run build:deploy
npm run verify:deploy
```

其中 `npm run verify` 验收本地全馆，`npm run verify:deploy` 验收压缩后的 `dist/` 发布包。任何一项失败都不创建正式版本。

## 4. 创建版本

```bash
git add -A
git commit -m "release: 发布 v0.2.0 人物馆与制度馆扩建"
git tag -a v0.2.0 -m "步入大明 v0.2.0"
```

如果已经配置远程仓库：

```bash
git push origin main
git push origin v0.2.0
```

## 5. 部署与线上验收

发布目录已链接到 Vercel 项目，部署命令应在 `dist/` 中执行：

```bash
cd dist
vercel --prod --yes
```

部署后回到项目根目录，用正式域名复核全部关键页面：

```bash
MING_DEPLOY_URL=https://ming-history-museum.vercel.app npm run verify:deploy
```

## 6. 回滚

页面出现严重错误时，优先在 Vercel 把上一个正常部署重新设为生产版本；代码层面从相应标签创建修复分支，不使用会抹除历史的强制重置：

```bash
git switch -c codex/hotfix-v0.2.1 v0.2.0
```

修复、验收后发布新的修订版本。旧标签保持不变，确保任何线上版本都能追溯到当时的代码和资料。
