# 土木堡之变人物作用图设计

## 目标

为“土木堡之变”专题增加完整的三阶段人物作用图，并在事件馆“土木堡之变”事件详情中增加与狭义事件范围相符的紧凑人物作用图及专题入口。

关系图回答“谁通过什么行动影响了谁或改变了局势”，不把人物同现自动解释为因果关系。

## 已确认的视觉方案

- 使用圆形人物头像，姓名置于头像下方。
- 使用三阶段切换：`亲征与战败`、`北京危机`、`复辟与清算`。
- 阶段标题和说明位于画布上方，不占用人物关系中心。
- 人物关系线使用 SVG 绘制，端点直接落在头像圆周。
- 动作关系使用方向箭头；箭头尺寸为 `10 × 10`。
- 动作线宽采用已确认第五版的 `.82`；身份或状态虚线采用 `.65` 且无箭头；两者均使用 `vector-effect: non-scaling-stroke`。
- 金线表示支持、任用、协作；红线表示冲突、俘获、清算；蓝灰虚线表示身份或状态关系。
- 关系标签带深色底，包含一个简短动作和一个辅助类型说明。
- 历史画像使用实线圆环；AI 想象像使用蓝灰虚线圆环并显示“AI想象像”。没有可靠头像时使用姓名首字占位，不临时生成新头像。
- 阶段结果置于画布下方，不作为人物或事件节点。

## 页面落位

### 专题页

目标页面：`exhibit-tumu-crisis.html`。

- 在现有“空间地图”之后、“谁在推动局势”人物卡之前新增“三阶段人物作用图”。
- 本图是专题完整版，三个阶段均可切换。
- 人物头像可点击，进入现有人物馆档案。
- 原有五张关键人物卡继续保留，关系图不替代人物档案。
- 专题侧边章节导航增加“人物作用图”锚点。

### 事件页

目标事件：`e033 · 土木堡之变`。

- 事件详情抽屉只展示第一阶段“亲征与战败”的紧凑图，人物限定为王振、朱祁镇、也先。
- 紧凑图不出现1450—1457年的复辟人物，避免把后续影响误标为狭义战役参与者。
- 图下增加“查看完整三阶段人物作用图”链接，指向 `exhibit-tumu-crisis.html#people-impact-graph`。
- 其他事件详情不显示关系图。

## 数据结构

新增 `data/ming_people_impact_graphs.json`，作为专题页与事件页的唯一关系来源。第一版只收录 `tumu-crisis`，但结构允许后续扩展其他事件与专题。

每张图包含：

- `id`
- `title`
- `exhibitionId`
- `eventId`
- `stages[]`
- `nodes[]`
- `edges[]`
- `outcome`
- `sources[]`

每条关系至少包含：

- `from`
- `to`
- `label`
- `note`
- `type`
- `directed`
- `confidence`
- `sourceIds`

节点位置作为经过人工审校的百分比坐标保存在各阶段数据中。渲染器根据节点圆心和半径计算线段端点，禁止把任意 CSS 短线伪装成连接线。

## 第一版关系

### 阶段一：亲征与战败

- 王振 → 朱祁镇：`影响亲征与行军`；程度解释标为中置信度，避免“王振一人导致战败”的单因叙事。
- 也先 → 朱祁镇：`率军围击 · 英宗被俘`；高置信度。

### 阶段二：北京危机

- 朱祁钰 → 于谦：`任用 · 组织防务`；高置信度。
- 也先 → 朱祁镇：`挟英宗施压`；高置信度。
- 朱祁镇 — 朱祁钰：`兄弟 · 皇位替代`；高置信度、无方向状态关系。

### 阶段三：复辟与清算

- 石亨 → 朱祁镇：`迎立英宗复位`；高置信度。
- 曹吉祥 → 朱祁镇：`参与发动政变`；高置信度。
- 朱祁镇 → 于谦：`裁决处死于谦`；高置信度。《明史·于谦传》记载英宗起初犹豫，经徐有贞进言后“帝意遂决”，因此箭头表达最终皇帝裁决，不表达朱祁镇亲自策划案件。

## 史实核对

- 故宫博物院“土木之变”条目支持也先率军、王振影响亲征与行军路线、英宗在土木堡被俘；其中具体兵力和伤亡数字不进入关系标签。
- 《明史》卷170《于谦传》支持于谦反对南迁、景帝采纳其防务部署、也先挟上皇进逼、石亨与曹吉祥等迎英宗复位，以及英宗对处死于谦作最终裁决。
- 现代研究用于限制单因叙事：关系图不把土木堡失败全部归罪于王振，也不把复辟与清算压缩成单人预谋。
- 数据源至少登记：故宫博物院“土木之变”、`《明史》卷170《于谦传》`、专题现有 Cambridge 中期危机研究。

## 渲染边界

- 专题页渲染器由 `scripts/build_ming_exhibitions.mjs` 生成完整三阶段组件。
- 事件页基础数据由 `scripts/build_ming_html.mjs` 嵌入，`scripts/build_ming_museum.mjs` 生成事件馆页面；只对 `eventId === 'e033'` 渲染紧凑图。
- 两处共用数据，不复制关系名单和关系措辞。
- 关系图加载或脚本执行失败时，原人物标签、事件详情和人物卡仍可使用。

## 响应式与可访问性

- 桌面端保持三阶段横向按钮和完整 SVG 画布。
- 390px 移动端阶段按钮仍为三列，但关系标签允许两行；不得出现横向滚动。
- 阶段按钮使用 `button`、`role="tab"`、`aria-selected`。
- 每个阶段 SVG 提供说明当前人物和关系的 `aria-label`。
- 不依赖颜色单独表达关系：标签文字同时说明动作类型。
- 遵循 `prefers-reduced-motion`，阶段切换不使用必要性动画。

## 验收标准

1. 专题页存在 `#people-impact-graph`，默认显示“亲征与战败”。
2. 点击三个阶段按钮后，人物、关系线、关系标签和阶段结果同步更新。
3. 每条关系线的起点和终点位于对应头像圆周，箭头不会停在空白区域。
4. 动作线存在明显 `10 × 10` 箭头；身份或状态虚线无箭头。
5. 专题页人物头像可进入对应人物档案。
6. `events.html?event=e033` 打开抽屉后显示三人紧凑图和完整专题入口。
7. `e033` 之外的事件抽屉不显示该组件。
8. 事件页紧凑图不出现朱祁钰、于谦、石亨或曹吉祥。
9. AI想象像有可见标签，不能被误认为历史原像。
10. 桌面端与390px移动端均无横向溢出、文字遮线或头像缺图。
11. `npm run build:museum`、`npm run build:deploy` 与 `npm run verify` 全部通过。

## 明确不做

- 不在本轮扩展其他五个专题。
- 不做全明朝自由拖拽关系网。
- 不根据人物同现自动生成关系。
- 不用力导向布局或随机位置。
- 不把争议性因果画成无条件确定事实。
