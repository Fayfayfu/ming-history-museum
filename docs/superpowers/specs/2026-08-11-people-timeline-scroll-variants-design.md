# 人物馆历史长卷 A/B/C 视觉方案设计

日期：2026-08-11
状态：已确认，待用户审阅书面规格

## 目标

在不破坏现有人物时间比例、泳道、头像选择、人物抽屉、横向浏览和 1000px 内总体高度约束的前提下，探索更接近“展开画轴长卷”的人物馆体验。

本轮不直接替换正式 `people.html`。先冻结当前版本，再分别制作 A、B、C 三个独立预览版本，最终由用户选择正式方案。

## 设计原则

1. 长卷感来自展开动作、阅读视窗和内容显露节奏，不依赖堆砌木纹、宣纸纹理等古风装饰。
2. 人物数据、年份比例、泳道位置、头像资源、人物抽屉和无障碍语义只能有一个事实来源，四个版本不得复制数据逻辑。
3. 四个版本的视觉变量必须足够独立，确保比较结论可解释。
4. 正式人物馆在用户完成选择前保持不变。
5. 任何动画都不能阻止搜索、选择人物、横向拖动或键盘操作。

## 独立保存方式

构建时生成四个互不覆盖的页面：

- `people-timeline-current.html`：当前人物长卷的冻结预览。
- `people-timeline-a.html`：克制型画轴。
- `people-timeline-b.html`：沉浸型观卷台。
- `people-timeline-c.html`：仪式型开卷。

四个页面共享人物数据、布局计算、头像加载、人物选择和抽屉逻辑。各版本只拥有自己的外壳结构、样式变量和必要的交互控制器。

当前版本同时以本设计实施前的 Git 提交作为恢复基线。生成页用于浏览比较，Git 历史用于完整恢复。

这些页面是内部预览入口，不加入正式博物馆主导航，也不进入搜索引擎索引。正式 `people.html` 仍保持当前版本，直到用户明确选择 A、B 或 C。

## 共享架构

### 共享长卷核心

共享核心继续负责：

- 163 人的时间定位和泳道布局；
- 严格按年份比例计算横坐标；
- 人物头像、姓名和身份；
- 当前视口头像分批加载、解码后显示和失败占位；
- 人物选中、发光外环、轴线引导和人物抽屉；
- 桌面、平板、移动端的横向滚动；
- 无 JavaScript 时的人物总表回退。

### 版本外壳

页面根节点使用明确的版本标记，例如 `data-scroll-variant="a"`。版本样式和控制器只能读取共享长卷的公开 DOM 结构，不得重新计算人物年份或泳道。

建议将版本差异拆成三个小单元：

1. `variant shell`：页面背景、画心、装裱和卷轴端部；
2. `variant motion`：开卷、边缘遮罩和拖动反馈；
3. `variant controls`：展卷、重播、返回人物馆等版本专用控制。

## 当前版：体验基线

当前版必须保持实施前的视觉和交互，不增加画轴装饰。它用于判断 A/B/C 是否真正改善体验，而不是作为第四个继续设计的方案。

验收重点：与正式 `people.html` 的人物位置、尺寸、颜色、页面高度和交互一致。

## A 版：克制型画轴

### 目的

验证在不改变人物馆信息结构的情况下，仅增加画卷材质、装裱边界和拖拽手感是否已经足够。

### 视觉

- 保留当前人物馆页面、导航、历史长卷/人物总表切换和约 1000px 高度。
- 长卷上下增加克制的装裱边，避免占用新的泳道空间。
- 左右边缘使用轻微卷曲、暗部和纸张厚度，不使用夸张木杆。
- 卷首加入小型题签，卷尾预留落款和印记；两者位于 1368 年之前与 1644 年之后的边界区，不覆盖人物。
- 时间轴继续清晰可见，不改造成装饰性墨线。

### 交互

- 长卷区域支持鼠标拖拽，光标使用 `grab` / `grabbing`。
- 触控板、滚轮、键盘和滚动条仍然可用。
- 拖动时只增加非常轻的纸面位移反馈，不增加惯性失控或弹簧回弹。
- 不自动播放开卷动画。

## B 版：沉浸型观卷台

### 目的

验证独立、沉浸的观看环境是否比人物馆内嵌长卷更适合长时间浏览。

### 视觉

- 页面成为接近全屏的观卷台，周围使用低亮度展陈背景，长卷保持明亮。
- 正式主导航缩为次级工具栏，但仍可返回人物馆和人物总表。
- 画卷占据首屏主要空间，画心、上下装裱和左右卷轴端部形成清晰层次。
- 视窗左右使用遮罩，表现内容从卷轴中出现和收入，而不是普通容器裁切。
- 总高度继续控制在 1000px 内；不得为了沉浸效果重新制造大面积空白。

### 交互

- 拖动长卷时，左右端部与纸面产生受控的相对运动，表达展卷/收卷方向。
- 横向滚动条保留为辅助控制，不隐藏可访问的滚动能力。
- 人物选中和抽屉保持原逻辑；抽屉打开后观卷台不丢失当前位置。
- B 版不强制播放完整开卷仪式，重点是稳定的沉浸阅读状态。

## C 版：仪式型开卷

### 目的

单独验证一次性的开卷仪式是否值得增加等待和动画成本。C 版以 A 版的明亮页面结构为基础，不叠加 B 版的暗色观卷台，避免变量混淆。

### 初始状态

- 首次进入显示收拢的卷轴、题签“明朝人物历史长卷”和明确的“展卷”按钮。
- 页面同时提供跳过入口；键盘焦点首先落在“展卷”按钮。

### 展开动作

- 点击“展卷”后，两端卷轴向左右分离，卷面在约 800ms 内显露。
- 人物、年份刻度和轴线跟随卷面裁切范围出现，不单独飞入或弹跳。
- 动画结束后彻底退出动画状态，页面变成正常可拖动长卷。
- 提供“重播开卷”，只用于比较或再次体验。
- 同一浏览会话默认只自动提示一次，不在每次返回人物馆时强迫等待。

### 动效降级

- `prefers-reduced-motion: reduce` 时跳过位移动画，直接进入展开状态。
- 动画执行中按 Escape、点击跳过或选择减少动态效果时立即完成展开。
- 动画资源或脚本失败时直接显示完整长卷，不能停留在收拢状态。

## 数据流

1. 构建器读取同一份人物数据和时间布局结果。
2. 共享渲染器生成同一份长卷核心 DOM。
3. 构建器为 current/A/B/C 注入独立外壳和版本标记。
4. 共享人物脚本处理头像、选择、抽屉和滚动位置。
5. A/B/C 控制器仅处理本版本的拖拽反馈、遮罩或开卷状态。

不得在版本控制器中存放人物名单、年份、身份、图片地址或影响力尺寸。

## 状态与恢复

- 每个版本使用独立 URL，不通过同一页面的临时 query 参数模拟。
- A/B/C 之间不共享动画状态；人物选择参数可继续使用现有 `person` 查询参数。
- B 版打开人物抽屉再关闭后，应回到原横向位置。
- C 版的“本会话已展开”只存储在 `sessionStorage`，清理会话后可重新体验。
- 最终选择某版时，将该版外壳接入正式 `people.html`，其余三个预览页继续保留一轮，确认上线稳定后再决定是否归档。

## 错误与降级

- 头像请求或解码失败：沿用现有文字占位，不影响长卷拖动。
- 版本专用 CSS 未加载：共享长卷核心仍可阅读。
- B 版遮罩或卷轴端部不支持：退化为普通横向容器。
- C 版动画中断：立即切换为完整展开状态。
- JavaScript 禁用：继续显示人物总表，不显示无法操作的收拢卷轴。

## 验收与测试

### 四版共同验收

- 四个 URL 均能独立打开，且正式 `people.html` 未被替换。
- 四版均为 163 个唯一人物、16 位皇帝，人物横坐标和泳道位置一致。
- 页面总宽度、严格年份比例、时间边界和人物影响力尺寸一致。
- 首屏与横向滚动后的可见头像均无需点击即可完成加载、解码和绘制。
- 人物点击、键盘选择、抽屉、移动端路由和无 JavaScript 回退不退化。
- 桌面宽 1440、平板宽 768、移动端宽 390 时页面主体不产生意外横向溢出；长卷自身允许横向滚动。

### A 版专项

- 装裱、卷首和卷尾不覆盖任何人物、姓名、身份或刻度。
- 拖拽、滚轮、触控板、键盘和滚动条都能移动长卷。
- 拖拽结束后不会残留抓取状态。

### B 版专项

- 观卷台首屏高度不超过 1000px。
- 左右遮罩不阻挡人物点击，也不遮挡当前视窗内的姓名和身份。
- 打开、关闭人物抽屉后保持横向阅读位置。
- 次级导航始终可见且处于选中人物之上。

### C 版专项

- 展卷、跳过、Escape 和重播均可达。
- 动画约 800ms，结束后不存在持续动画计时器或交互遮罩。
- 减少动态效果时直接展开。
- 动画或脚本异常时自动显示完整长卷。

### 视觉对比证据

为 current/A/B/C 各保存同一视口、同一横向位置的桌面截图；另为 B 保存观卷台全景，为 C 保存收拢、展开中和展开后三个状态。截图用于比较，不作为唯一验收依据。

## 明确不做

- 不修改人物史实、年份、分类、评分、影响力名单或头像资源。
- 不为三个方案复制三份人物数据。
- 不加入声音、自动旁白、背景音乐、粒子、落叶或持续漂浮动画。
- 不在用户选择前替换正式人物馆。
- 不在本轮同时重做人物抽屉、人物总表或全站导航。

## 实施顺序

1. 冻结 current 页面并建立恢复基线。
2. 实现共享版本构建入口和共同回归测试。
3. 实现 A，打开独立页面供用户查看。
4. 保留 A，实现 B，打开独立页面供用户查看。
5. 保留 A/B，实现 C，打开独立页面供用户查看。
6. 完成四版同位截图和全量验证。
7. 用户选择后，另开一次小范围变更将选定方案接入正式 `people.html`。
