# 明朝制度馆 C 版：宫廷权力空间与 P1 机构扩展设计

- 状态：已完成对话确认，等待书面规格审阅
- 日期：2026-08-10
- 项目：步入大明｜数字历史博物馆
- 产品定位：保留 B 版浅色「明代官制档案」，新增独立 C 版「宫廷权力空间」预览页
- 历史边界：本页表达权力、文书与机构关系，不是紫禁城建筑平面复原，也不是跨越 276 年的单一静态组织树

## 1. 背景与问题

当前 `institutions.html` 使用 29 个规范节点、47 条关系、4 个宏观时间切片、6 种阅读视图和 16 个来源，能解释皇帝、内阁、六部、监察司法、厂卫、军事及地方治理的权力主干。

这一版本作为「明代权力主干图」成立，但作为完整的「制度馆」覆盖不足：翰林院、国子监、礼仪专业机构、宗人府、东宫机构、内廷二十四衙门及京师治理尚未形成分层阅读空间。

C 版不以「同屏塞入更多节点」解决问题，而是采用渐进展开：

> 轴线上保留 29 节点权力主干；走近外朝、内廷、东宫、礼仪文教、京师军政等空间时，再打开相应的制度房间。

## 2. 目标

1. 在不破坏 B 版已验证内容的前提下，新增一个独立 C 版。
2. 将规范图节点数由 29 个扩展为 45 个，其中本批新增 16 个规范机构；默认仍以 29 节点权力主干作为入口。
3. 把规范机构、结构合称、子机构、职位荣衔和证据边界视觉区分。
4. 保留现有「4 个宏观切片＋选中年份状态」时间模型，不把不同时期的机构和权力写成永久并存。
5. 桌面端兼具结构图与展览感；移动端改为纵向制度章节，不缩小桌面关系图。
6. 将字体、对比度、连接线、焦点和减少动效纳入硬性验收。

## 3. 非目标

- 不修改 B 版 `institutions.html` 的 29 节点和 47 条关系。
- 不把 C 版加入正式主导航。
- 不收录《明史·职官志》中所有官署。
- 不把五寺、三法司、二十四衙门等合称伪装成统一机关。
- 不把总兵、临战统帅、太子三师三少、三公三孤建成机构节点。
- 不用没有直接来源的「有关」「影响」或「类似上下级」补线。
- 不在本批扩展南京留都、九边、土司及王府完整制度。

## 5. 空间架构

### 5.1 总体形式

C 版采用「轴线驻留＋侧室推开」：

- 中轴始终承载 29 节点 P0 权力主干。
- 用户滚动到某个制度段落时，相应房间轮廓和入口亮起。
- 用户确认进入后，房间从中轴侧面展开，权力主干不离场。
- 同一时刻只能展开一个制度房间。
- 关闭房间后回到原轴线位置，选中年份和阅读进度不丢失。

空间只是权力关系的展览隐喻。不绘制仿古宫殿、宫门、柱列、平面图或中国建筑群复原，避免产生虚假地理含义。

### 5.2 五个制度房间

| 房间 | 主要内容 | 在主干中的锚点 |
|---|---|---|
| 内廷 | 司礼监、厂卫、二十四衙门 | 皇帝—司礼监—厂卫 |
| 东宫与宗室 | 宗人府、詹事府、左右春坊、司经局 | 皇族与中枢边界 |
| 礼仪文教 | 翰林院、国子监、四寺、钦天监、太医院、尚宝司 | 礼部、内阁及皇帝门户 |
| 外朝政务 | 内阁、通政使司、六部、都察院、六科、大理寺 | 文书、票拟、裁决、执行、监察司法 |
| 京师军政 | 顺天府、五城兵马司，以及 P0 军事、卫所和地方主干 | 五军都督府—都司—卫所及地方治理 |

## 6. 房间内部的四层视觉语法

| 层级 | 视觉形式 | 数据能力 |
|---|---|---|
| 规范机构 | 实线机构卡 | 可作关系端点，可打开机构档案 |
| 结构合称 | 虚线分组框 | 只组织阅读，不是关系端点 |
| 职位与荣衔 | 窄条职位牌 | 说明人如何站上权力位置，不连入机构网 |
| 时间、争议与证据边界 | 朱批签 | 承载变化、不确定性和禁止泛化的说明 |

跨房间机构不重复建点，而以「房间入口」引用唯一规范节点。例如大理寺在三法司中保留唯一节点，礼仪文教房间的「五寺」只通往该节点。

## 7. 时间模型

1. 全局年份是中轴、房间、关系线和机构档案的唯一时间状态。
2. 房间在年份切换时保持打开，滚动位置不改变。
3. 当年活动的规范机构使用实线卡，可作关系端点。
4. 「阶段内反复设置／精确开闭未核实」使用斜纹卡并显示明文，不通过颜色暗示精确状态。
5. 未设、已罢或此年不活动的机构不进入活关系图，只出现在房间变化记录中。
6. 若用户已打开的机构随年份变为不活动，机构卡退出活关系图，但档案转换为「历史踪迹卡」，说明原因并提供可跳转的活动年份。
7. 任何时候只绘制选中年份内可证的关系。

## 8. 视觉和响应式

### 8.1 视觉气质

- 保留 C 版「宫廷权力空间」的戏剧性，但不使用黑底、黑卡、微弱彩边和细白字。
- 主画面使用浅宣纸、深褐文字、朱砂焦点和明确的系统卡面。
- 标题、副标题和导览置于关系画布之外，不覆盖节点。
- 不使用建筑柱列、宫殿屋顶或红色几何装饰冒充制度结构。

### 8.2 断点

| 宽度 | 阅读形式 |
|---|---|
| `>=1100px` | 驻留中轴舞台＋滚动叙事轨＋侧室展开 |
| `720—1099px` | 全宽舞台＋画布下方说明，不并排狭窄叙事轨 |
| `<=719px` | 纵向制度章节，房间在当前章节下方原位展开 |

移动端不渲染微缩自由关系画布，不要求横向拖拽。关系以有顺序的文字路径表达，机构档案以底部抽屉显示，高度不超过当前可视区 82%。

### 8.3 可读性与可访问性合同

- 禁止对中文字形使用 `scaleX`、`font-stretch` 或其他人工横向压缩。
- 普通文字对比度至少 4.5:1。
- 普通关系线视觉宽度不低于 2px，聚焦关系线不低于 3px。
- 连接线端点必须依据机构卡实时边界计算，不允许用固定百分比猜测终点。
- 窗口尺寸、断点或房间状态变化后必须重新计算线端点和关系标签。
- 所有房间、机构和档案均可通过键盘打开和关闭。
- `Escape` 关闭房间或档案后，焦点返回原触发对象。
- `prefers-reduced-motion: reduce` 下取消空间位移、缩放和过渡，但保留明确状态变化。

## 9. 数据与构建架构

### 9.1 基础数据保持不动

`data/ming_institution_graph.json` 继续是 B 版的唯一机构图来源，必须继续通过现有硬编码的 29 节点、47 关系、6 视图及 16 来源验证。

### 9.2 扩展数据

新增 `data/ming_institution_expansion.json`，包含：

- `institutions`：16 个新规范机构。
- `systems`：C 版新增的专业文教、东宫宗室、京师治理和内廷服务系统定义。
- `structural_groups`：6 个新结构组。
- `subinstitutions`：23 个新内廷子机构档案。
- `rooms`：5 个房间及其规范节点、结构组和子机构成员。
- `relations`：通过 P1 内容基线审校的新关系。
- `sources`：新增来源。
- `person_links`：新机构与现有人物卡的可证任职、创设或制度塑造关系。

扩展关系数量不在本设计文档中预设。实施计划的第一个内容任务必须完成 P1 关系基线，将已审核关系总数固化为校验常量后，才允许关系图实现进入绿色状态。这是证据门槛，不是未决策的功能项。

### 9.3 组合模型

C 版构建器读取 P0 基础图和 P1 扩展层，在内存中生成 45 个唯一规范节点的组合模型。组合阶段必须拒绝：

- 重复 ID。
- 同一历史实体的变体名重复建点。
- 结构组或职位牌出现在关系端点。
- 未知关系类型。
- 无来源、无时期或无边界的规范节点。
- 关系时期超出任一端点活动期。

### 9.4 页面和导航

- B 版继续由现有 `scripts/build_ming_institutions.mjs` 生成 `institutions.html`。
- C 版使用独立构建器生成 `institutions-palace.html`。
- 正式主导航仍只链接 `institutions.html`。
- C 版顶部必须有「返回明代官制档案」链接。
- C 版可进入构建和部署包，但只通过直接地址访问。

## 10. 异常与降级

| 情况 | 行为 |
|---|---|
| 扩展文件缺失或 JSON 不合法 | C 版构建失败，不生成半成品 |
| 新节点缺少来源、时期或边界 | 扩展数据校验失败 |
| 只能证明机构存在，不能证明关系方向 | 允许进入机构档案，但关系不进图 |
| 房间在选中年份无活动机构 | 显示「这一年份暂无可展示的活动机构」，不显示空白画布 |
| 精确开闭时间未核实 | 显示「反复设置／精确区间未核实」，不自动补全 |
| 已选机构随年份失效 | 档案转为历史踪迹卡，保留焦点和可跳转年份 |
| 跨房间目标未通过组合校验 | 不渲染入口，不留断线 |
| JavaScript 不可用 | 显示静态房间目录、基本说明和返回 B 版链接 |

## 11. 验收标准

### 11.1 数据

- P0 仍为 29 节点、47 关系、6 视图和 16 来源。
- P1 扩展层恰好有 16 个新规范节点、6 个结构组和 23 个新内廷子机构。
- 组合后恰好为 45 个唯一规范节点。
- 尚宝司和尚宝监是不同实体；左春坊和右春坊分别建点。
- 关系的 `from` 和 `to` 仅能指向规范机构 ID。
- 每个新规范机构在进入 C 版活关系图前，至少有一条通过内容基线审核的有效关系。

### 11.2 桌面端

在 1440px、1024px 及超宽屏检查：

- 标题和说明不覆盖关系画布。
- 活动机构卡不碰撞。
- 可见关系标签不压住机构卡。
- 连接线端点与机构卡边界的视觉偏差不超过 3px。
- 窗口缩放、断点变化和房间开闭后，线端点仍正确。
- 同一时刻只有一个房间展开。
- 房间展开后 P0 权力主干仍可辨识。
- 机构档案打开和关闭不引发画布重排。

### 11.3 移动端

在 390×844 检查：

- 渲染纵向制度章节，不渲染微缩自由关系图。
- 当年活动机构和有效关系均有可读文本表达。
- 房间在当前章节下方展开。
- 档案抽屉高度不超过可视区 82%。
- 年份切换后，房间、档案和焦点状态符合第 7 节。

### 11.4 可访问性

- 普通文字对比度至少 4.5:1。
- 机构卡边界满足非文字对比要求。
- 普通关系线不低于 2px，聚焦关系线不低于 3px。
- 机构、房间、年份和档案均可键盘操作。
- 关闭后焦点返回原触发对象。
- 减少动效模式下没有空间位移和过渡。
- 页面不包含中文字体横向压缩。

### 11.5 回归与部署

- 现有 `verify:institutions`、`verify:institution-layout`、`verify:institution-page` 继续通过。
- 新增扩展数据验证、组合模型验证和 C 版浏览器合同。
- 全站回归继续通过。
- 部署包包含 `institutions-palace.html`。
- 正式主导航不包含 `institutions-palace.html` 链接。
- C 版可返回 `institutions.html`。

## 12. 实施顺序

1. 产出 16 个新规范机构、6 个结构组、23 个子机构和新关系的 P1 内容补充基线。
2. 完成来源、时期、实体类型和关系方向审校，固化扩展关系数量。
3. 编写扩展数据验证合同，在没有生产数据时确认 RED。
4. 建立 `ming_institution_expansion.json` 并使数据验证 GREEN。
5. 编写 C 版组合模型和页面浏览器合同，确认 RED。
6. 实现组合模型、C 版独立构建器和渲染器。
7. 实现中轴、制度房间、年份状态、机构档案和历史踪迹卡。
8. 实现中屏和移动端纵向章节。
9. 完成字体、对比度、线端点、焦点和减少动效验收。
10. 运行 B 版专项回归和全站回归。
11. 生成 `institutions-palace.html` 及桌面、移动端预览，将页面纳入部署包但不加入主导航。

- [故宫博物院：詹事府](https://www.dpm.org.cn/court/system/236420.html)。
- [故宫博物院：翰林院](https://www.dpm.org.cn/court/system/236391.html)。
- [故宫博物院：司礼监](https://www.dpm.org.cn/court/system/236401.html)。
- [故宫博物院：太医院](https://www.dpm.org.cn/court/system/236424.html)。
