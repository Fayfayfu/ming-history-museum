# 人物馆按需数据加载设计

## 目标

将人物馆首页 `people.html` 从“内嵌全量人物、事件、关系与叙事数据”的单页，改为“首屏加载索引；打开人物或事件时再加载相应详情”的纯静态站结构。独立人物页继续保持预生成 HTML，不改变现有 URL。

首要指标是减少首屏 HTML 的传输与 JavaScript 解析负担，而不是以牺牲筛选、深链接或证据入口为代价。当前约 1.8 MB 的 `people.html` 应降至 300 KB 以下；实际目标以构建后的字节数验收。

## 范围与非目标

### 范围

- 人物馆首页的人员列表、筛选、搜索、抽屉、事件详情和 URL 深链接。
- 构建时从现有 JSON 数据生成索引与详情 JSON。
- 详情加载的占位、失败提示与重试。
- 输出完整性、深链接、筛选和首屏体积的自动检查。

### 非目标

- 不改人物独立页的生成方式、文案或 URL。
- 不改历史数据内容、人物卡结构或视觉设计。
- 不引入后端、数据库、账户体系或运行时 API。
- 不承诺 `file://` 直接打开时可加载抽屉；本地预览改用静态 HTTP 服务。

## 架构

构建后新增静态数据目录：

```text
assets/data/
  people-index.json
  people-details/<stable-person-id>.json
  events-index.json
  event-details/<event-id>.json
```

`people.html` 仅保留页面骨架、交互代码及必要的极小配置。首屏启动后请求 `people-index.json` 与 `events-index.json`，以它们渲染统计、人物网格、搜索、筛选和事件入口。

人物索引必须包含不打开抽屉也要使用的字段：稳定 ID、姓名、类别、官职摘要、出生与死亡年、领域、机构摘要、头像路径及标签、关系与事件 ID、评分摘要、独立页 URL。事件索引包含事件 ID、标题、年份/年号、阶段、摘要和相关人物 ID。索引不得携带叙事正文、逐幕证据、作品长描述或关系解释全文。

每个详情 JSON 只包含对应抽屉所需内容：完整人物数据、关系说明、机构详情、时间线、速览、独立页摘要与入口、相关事件摘要、作品及证据入口。事件详情 JSON 只包含事件抽屉所需正文、影响、史料与关联实体。

## 交互与数据流

1. 首页加载索引后，立即可筛选、搜索和浏览人物卡。
2. 点击人物卡时，页面以稳定 ID 请求 `people-details/<id>.json`。成功后渲染抽屉；同一人物再次打开复用内存缓存并保留已有阅读位置。
3. 点击新人物时，抽屉回到顶部；沿用现有行为。
4. 点击事件时，以同样方式请求 `event-details/<id>.json`。
5. `?person=姓名` 和 `?event=ID` 深链接先解析索引，再自动请求详情并打开相应抽屉。
6. 请求期间抽屉展示简洁加载态；请求失败时说明“详情未能载入”，提供重试，并保留返回人物列表的能力。

稳定 ID 必须来自现有可复用的 slug / event ID，不能以数组顺序或显示文本作为文件名。姓名仍用于兼容既有 URL 查询参数。

## 缓存与部署

详情 JSON 与索引均作为构建产物部署至 `dist`。它们采用静态资源缓存策略；每次发布由新部署 URL 保证版本一致性。页面运行时只做内存缓存，不写入 localStorage，以避免旧历史数据长期残留。

本地需要通过静态 HTTP 服务预览，例如构建后的 `dist` 目录；`file://` 因浏览器跨源限制不作为支持路径。

## 构建与验证

构建脚本应从当前数据源生成 JSON，并保证：

- 索引中的每个详情 URL 都存在且 JSON 可解析。
- 每位人物与每个事件的详情仅出现一次；索引 ID、详情 ID 与源数据一致。
- 所有已有独立页入口、头像、机构、相关事件与作品链接继续有效。
- `people.html` 不再内嵌完整 `personPages`、`storytelling`、`historicalSlices`、全量事件正文或全量作品正文。
- 构建后 `people.html` 小于 300 KB；索引和详情文件总数与数据对象数相符。
- 浏览器回归覆盖首屏渲染、人物/事件加载、失败重试、筛选、搜索、`?person=` 与 `?event=` 深链接，以及同人物/不同人物的滚动行为。

## 风险与处理

- **首次点开抽屉多一次请求：** 仅加载该人物详情；用加载态和内存缓存减少感知等待。
- **索引字段遗漏导致列表功能退化：** 先以当前筛选、搜索与统计访问字段反推索引 schema，并在验证器中检查。
- **JSON 与 HTML 输出不同步：** 同一构建命令中生成页面与 JSON；验证器检查所有引用文件。
- **本地文件预览失效：** 在文档和预览链接中明确使用静态 HTTP 服务，而非 `file://`。

## 成功标准

1. 首页首屏保持可用，人物列表、统计、搜索和筛选不依赖详情文件。
2. 人物和事件抽屉按需加载，深链接与现有阅读位置规则不回退。
3. 独立人物页、证据入口、相关事件、作品展示和机构链接保持原样可用。
4. `people.html` 构建产物小于 300 KB，并通过完整性与浏览器回归验证。
