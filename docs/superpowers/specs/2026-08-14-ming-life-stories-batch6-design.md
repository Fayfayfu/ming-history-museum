# 人物文案第六批：于谦、唐寅、戚继光差异化展陈设计

日期：2026-08-14
分支：`codex/life-stories-batch6`
状态：用户已确认设计方向，等待书面规格复核

## 一、背景

人物馆现有独立页已经形成一套可复用的清晰传记结构：人物卡负责快速建立生平轮廓，独立页使用五至六个有明确年代与年号的阶段展开，并在每一阶段区分史实、解释和证据边界。

于谦、唐寅、戚继光目前仍是较早版本：独立页各只有三幕，人物卡与独立页之间的信息密度不足，部分人物卡来源仍使用百科或泛古籍入口。三人的历史作用不同，不能统一套用“生平加作品展厅”模板。

本批遵循一条核心原则：**统一证据标准与阅读清晰度，不统一人物的展示重点。**

## 二、目标

1. 同步优化于谦、唐寅、戚继光的人物基础卡、抽屉速览与独立页。
2. 将每人独立页扩展为五至六个有内容意义的人生阶段，补齐公历、年号、速览、正文、史料依据与解释边界。
3. 按人物的主要历史作用选择不同的专题机制：
   - 于谦：危机决策与政治责任；
   - 唐寅：作品、文化身份与职业生存；
   - 戚继光：军事组织、训练方法与制度约束。
4. 《明史》不足时，使用《明实录》、本人文集或著作、作品题跋、博物馆藏品页和可靠研究补足。
5. 保持人物卡简短；作品扩展主要发生在独立页，不把抽屉重新做成长页面。
6. 保持郑和现有优化版不变，并以对象级比较锁定。

## 三、非目标

1. 不把三人都改成作品型人物页。
2. 不重做人物馆通用抽屉布局。
3. 不重写朱元璋、朱棣、郑和及第五批人物数据。
4. 不因资料不足而补写心理独白、现场对白或无法核验的传奇细节。
5. 不把现代策展摘要伪装成历史人物原句。
6. 本批只交付本地分支与预览；合并、推送和上线需用户另行确认。

## 四、统一内容协议

### 4.1 人物基础卡

每人的 `data/ming_core.json` 记录应满足：

- `summary` 用两至三句说明主要作为，不使用标签式短语；
- `evaluation` 同时说明历史贡献、能力边界与政治或社会代价；
- 至少两个可直接核验的主要来源；
- 不再使用维基百科或泛古籍首页作为主要来源；
- 来源说明区分正史、实录、本人著作、博物馆资料和现代研究。

### 4.2 抽屉与独立页共用数据

三人的人物速览与独立页继续共用 `data/ming_person_pages.json`：

- `readingMode` 统一为 `clear-biography`；
- 每人五至六幕；
- 每幕必须有 `year`、`reignYears`、`age`、`kicker`、问题驱动标题和 `preview`；
- 每幕正文至少两段，第一段交代发生了什么，第二段解释意义或边界；
- 每幕必须有 `evidenceNote`、`confidence`、`primarySource` 与 `interpretationBoundary`；
- 抽屉只使用问题、概述和逐幕速览，不加入作品缩略图；
- 移动端保持直接进入独立页的既有行为。

### 4.3 史料层级

检索顺序不是机械堆叠，而是由问题驱动：

1. 先读《明史》本传，确定生平骨架与材料缺口；
2. 回查《明实录》中的任命、事件、奏议、奖惩和身后处置；
3. 使用本人著作、文集、题跋或同期材料核对方法和自我表述；
4. 使用博物馆藏品页核对作品名称、材质、尺寸、年代、收藏与图像来源；
5. 使用可靠现代研究解释争议，不以研究推断替代原始材料。

材料冲突时：

- 页面明确写出不同说法；
- 不能判定时标注中、低或未知置信度；
- 不以“择一讲得更顺”为理由消除争议；
- 无法形成有意义叙事的材料缺口可以保留，不用套模板补齐。

## 五、人物差异化设计

### 5.1 于谦：危机决策与政治责任

核心问题：**当皇帝被俘、京军主力覆没时，于谦怎样让朝廷重新具备决策和执行能力；八年后，这套选择为什么又被改写成罪证？**

建议六幕：

1. 早年入仕与地方治理：说明其并非在土木之变当天才具备行政经验；
2. 河南、山西等地巡抚经历：展示赈济、军政与地方协调能力；
3. 1449 年土木败报抵京：反对南迁、确立监国和防守秩序；
4. 北京保卫战：兵员、城防、号令、谈判与迎归太上皇之间的选择；
5. 景泰朝的兵部中枢：危机结束后如何继续处理军政与权力关系；
6. 1457 年夺门、处死与身后平反：区分法律指控、政治需要和后世忠臣叙事。

专属模块为“危机决策链”，而不是作品画廊。模块依次显示：已知信息、未知风险、可选方案、实际决定、短期结果、长期政治代价。

作品与文本只作为证据：

- 《石灰吟》保留，但明确归属、字句版本和“少年作”说存在争议；
- 从《于忠肃集》或可靠文本中选择一至两项奏议、诗文，说明其政治语言与后世形象；
- 不把诗作与其结局机械解释为命运预言。

优先来源：

- 《明史》卷一百七十《于谦传》；
- 《明英宗实录》及相关实录条目；
- 《于忠肃集》或可靠整理本；
- 故宫博物院及可靠学术研究。

### 5.2 唐寅：作品、文化身份与职业生存

核心问题：**科举正途关闭以后，唐寅怎样依靠诗、书、画和个人名声谋生；后世“风流才子”形象又遮蔽了什么？**

建议六幕：

1. 苏州成长、学习网络与家庭变故；
2. 1498 年乡试解元：才名与士人正途的高点；
3. 1499 年会试案：区分正史记载、案情不明处和后世传奇；
4. 仕途断裂后的旅行、交游与身份调整；
5. 以书画、诗文和题跋参与市场：客户、名声与职业生产；
6. 晚年、身后传播与“唐伯虎”公众形象形成。

专属模块为“作品展厅”。作品是解释其历史位置的主要材料，而不是生平之后的装饰。

作品区要求：

- 展示四至六件可追溯作品；
- 每件包含题名、年代或年代范围、材质、尺寸、馆藏、图像来源、作品解读和置信度；
- 优先使用可合法展示的公共领域图像或博物馆明确开放资源；
- 作品选择兼顾山水、人物、花竹或诗书关系，不只展示同一题材；
- 归属有争议的作品必须标注“传”“款”或争议状态；
- 不使用“画如其人”式单线心理解释。

候选来源体系：

- 《明史》卷二百八十六《文苑·唐寅》；
- 唐寅文集、题跋与可核验诗文；
- 故宫博物院、台北故宫、大都会艺术博物馆、史密森尼或其他可靠馆藏页；
- 关于吴门艺术、职业画家市场和唐寅接受史的现代研究。

最终作品清单由图像权利、馆藏元数据完整度和页面可访问性决定，不在设计阶段预设无法核验的作品。

### 5.3 戚继光：军事组织与训练方法

核心问题：**戚继光的优势不是发明一次奇袭，而是把募兵、编组、武器、号令、军纪和后勤变成可以重复训练的体系；为什么这套体系仍难以脱离特定财政与政治条件长期运行？**

建议六幕：

1. 世袭武职、登州与早期边防经验；
2. 浙江抗倭初期：旧有兵制为何难以形成稳定战斗力；
3. 募兵、编组与训练：所谓“戚家军”怎样被组织出来；
4. 台州及闽粤作战：地形、兵器配合、情报和后勤怎样共同作用；
5. 蓟镇时期：面对北方边防重新设计训练、城防与火器配置；
6. 张居正去世后的失势、著作传播与军事遗产。

专属模块为“训练系统剖面”，而不是兵书作品展。模块应把方法拆成：选兵、编组、器械、号令、赏罚、地形、补给和复盘。

著作作为操作证据：

- 《纪效新书》用于说明南方作战、编组和训练方法；
- 《练兵实纪》用于说明北方蓟镇环境下的方法调整；
- 可增加一项诗文或文集材料，但不与两部兵书并列为主要展示轴；
- 展示原书图页或阵法图时，必须核对版本、图页来源和版权；
- 页面明确区分戚继光原文、书中图示、现代操作摘要。

优先来源：

- 《明史》卷二百一十二《戚继光传》；
- 《明实录》相关任命与战事条目；
- 《纪效新书》《练兵实纪》《止止堂集》；
- 故宫博物院、军事史研究与可靠版本资料。

## 六、页面与数据实现边界

### 6.1 复用现有结构

- 基础卡继续由 `data/ming_core.json` 提供；
- 抽屉速览与独立页继续共用 `data/ming_person_pages.json`；
- 生成逻辑继续使用 `scripts/build_ming_html.mjs` 与 `scripts/build_ming_person_pages.mjs`；
- 不把本批数据复制到 `data/ming_storytelling.json`，避免同一人物出现两个相互漂移的版本。

### 6.2 差异化专题组件

在现有 `feature` 体系内增加或调整三种语义明确的类型：

- 于谦：`crisis-decision`；
- 唐寅：沿用或扩展 `gallery`；
- 戚继光：`training-system`。

组件可以共享基础布局函数，但数据字段、标题语言和信息层级必须体现不同人物问题。不得只换图标和颜色后继续使用同一组“概念卡”。

### 6.3 图像处理

- 唐寅作品图像下载到项目既有作品资产目录；
- 文件名包含人物、作品简称和来源批次，避免无语义哈希名；
- 数据记录原始馆藏页、图像许可或公共领域状态；
- 下载失败、来源限制或元数据不完整时，减少作品数量，不用低可信替代图补位；
- 于谦与戚继光不为满足视觉数量强行寻找无关配图。

## 七、验收标准

新增第六批专项验证，至少检查：

1. 三人基础卡摘要、评价和两个主要来源完整；
2. 三人均为 `clear-biography`，有五至六幕；
3. 每幕公历、年号、年龄、标题、速览、正文、史料、原文入口与解释边界完整；
4. 禁止出现“生卒与出身”“进入历史现场”“主要行动与位置”“结局与历史影响”等套模板标题；
5. 于谦页面存在危机决策链，不要求大型作品画廊；
6. 唐寅页面存在四至六件作品，图片可加载、元数据与来源完整；
7. 戚继光页面存在训练系统剖面，并明确展示《纪效新书》与《练兵实纪》的不同使用环境；
8. 三人抽屉保持简短，桌面无横向溢出；
9. 390px 下正确进入独立页，页面无横向溢出；
10. 郑和基础卡和独立页对象与本批开始前完全一致；
11. `audit:museum`、`audit:portraits`、全人物故事、年号检查和全站 `npm run verify` 通过；
12. `build:deploy` 与 `verify:deploy` 通过，但不自动上线。

## 八、风险与处理

### 8.1 作品图像版权与下载稳定性

唐寅作品优先使用公共领域或明确开放图像。馆藏页可访问不等于图片可自由再发布；许可不清时只保留文字展签和馆藏链接。

### 8.2 原典版本差异

诗文、兵书和文集可能存在不同版本。页面引用必须记录版本或来源页面；无法确认时使用短引文并标注边界，不拼接不同版本。

### 8.3 正史的后见之明

《明史》对于忠臣、名将和文人的叙述都经过清代修纂。页面使用正史建立问题，但不能把正史评价直接当作事件当时所有人的共同判断。

### 8.4 展示重点再次模板化

专项验证不仅检查数量，还检查语义锁：于谦必须围绕危机与责任，唐寅必须以可核验作品为主轴，戚继光必须围绕组织与训练。若三页专题模块可以互换人物姓名而成立，即视为设计失败。
